# rootfs 目录与 Git 策略

## 目录是什么

`rootfs/` 是 **initramfs（cpio）的源树**，由 `make rootfs` → `script/rootfs/build_cpio.sh` 打成 `build/rootfs.cpio`，再链进内核镜像。

两层内容（不要混为一谈）：

| 类型 | 路径示例 | 来源 | Git |
|------|----------|------|-----|
| **测例数据（fixtures）** | `text.txt`、`cpio_probe.txt`、`mnt/` | 仓库维护、手改 | **应提交** |
| **测例程序（generated）** | `tests/*` ELF、`tests/manifest`、`tests/run_all.sh` | `make user` / `pack_user_rootfs.py` 生成 | **不提交** |
| **可选 busybox** | `bin/busybox`、`init`→`bin/busybox` | `build_busybox.sh`（产物缓存 `.cache/busybox-$ARCH/`；`FORCE_BUSYBOX=1` 全量重建） | **不提交** |

`tests/run_all.sh` 由 `pack_user_rootfs.py` **按 manifest 顺序展开**（显式 `run_one`），不是手写 `while read`：ash 的 poll+逐字节 read 会走嵌套 VFS→cpio IPC，bring-up 阶段易挂。manifest 文件仍打进 cpio 供核对。

manifest 是 CPIO 上的普通文件 `/tests/manifest`，与 ELF 一样可由 VFS 读取（见 [`FILE_LOADING.md`](FILE_LOADING.md)）。

**不要混淆的路径：**

| 你看到的 | 实际含义 |
|----------|----------|
| 仓库 `rootfs/text.txt` | cpio 源文件 → 启动后 VFS 路径 `/text.txt` |
| 仓库 `rootfs/tests/*` | `make user` 生成 → cpio `/tests/*` |
| 仓库根 `tests/`（错误） | 历史/误生成目录，**不应存在**；已在 `.gitignore` 忽略 |
| VFS `/text.txt` | initramfs 内文件，不是仓库根目录文件 |

演进待办见 [`VFS_EVOLUTION.md`](VFS_EVOLUTION.md)。

## .gitignore 建议

**不要把整个 `rootfs/` 写进 gitignore。**

fixtures 需要进仓库，否则干净 clone 后 `make rootfs` 打出来的 cpio 缺 `text.txt` 等，open/read 测例会失败。

当前 `.gitignore` 规则（推荐保持）：

```gitignore
# Generated by make user (cpio test ELFs + manifest + run_all.sh)
rootfs/tests/*
!rootfs/tests/.gitkeep

# Optional local busybox + /init symlink
rootfs/bin/*
!rootfs/bin/.gitkeep
rootfs/init
```

含义：

- `rootfs/tests/*`：所有 `make user` 产物忽略；
- `rootfs/init`：`build_busybox.sh` 创建的 symlink，忽略；
- fixtures（`text.txt`、`mnt/`、`cpio_probe.txt`）**不在 ignore 里**，应 `git add` 进仓库。
- 源脚本：`script/rootfs/boot_smoke.sh`（可选 smoke）；`run_all.sh` **只在** `rootfs/tests/` 由 pack 生成，仓库不放模板副本。

## 常用命令

```bash
make user ARCH=x86_64      # 构建测例 ELF → rootfs/tests/ + manifest
make rootfs ARCH=x86_64    # 刷新 build/rootfs.cpio
make ARCH=x86_64 build run
```

若 `git status` 显示 `rootfs/` untracked：通常是 fixtures 尚未 add；`tests/` 里大量 ELF 应被 ignore，只剩 `.gitkeep` 可见。
